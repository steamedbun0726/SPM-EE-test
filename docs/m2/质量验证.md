# M2 质量验证：故障注入记录

> 任务书要求：「测试必须确实验证了行为；验证手段：故意破坏实现，观察测试是否失败。」
> 本文记录 M2 在 2026-11-03 这一轮改造中实际执行的故障注入（mutation）实验，
> 证明测试不是「看起来完整但什么都没测」。

## 方法

1. 修改被测实现，人为引入一类缺陷；
2. 只运行 M2 测试套件（`npx jest test/m2-rooms.spec.ts --runInBand`）；
3. 记录失败用例；
4. 还原实现，确认重新全绿。

还原后必须与注入前逐字一致，否则视为实验无效。

## 实验记录

### 注入 1：丢失时间维度（复现原缺陷）

- **改动**：审批通过写入占用时，把 `date: request.date` 改为固定值 `'1970-01-01'`，
  模拟旧实现「占用不绑定具体日期」的缺陷。
- **预期**：与时间维度相关的用例失败。
- **实际**：

```
● 撤销：approved 撤销后释放占用，座位重新可约
● 回归：审批通过只占用该时段，同一教室其他日期/时段仍可预约
Tests: 2 failed, 14 passed, 16 total
```

- **结论**：回归用例确实守住了原始缺陷。若将来有人把占用写成与日期无关，
  这两条用例会立刻变红。

### 注入 2：移除审批独立性校验

- **改动**：删除 `loadForReview` 中「同一审批人不能连续完成两级」的判断。
- **预期**：审批独立性用例失败。
- **实际**：

```
● 审批独立性：同一审批人不能连续完成两级
Tests: 1 failed, 15 passed, 16 total
```

- **结论**：多级审批的独立性不是靠注释保证的，而是有测试兜底。

## 局限与后续

- 本轮只做了 2 次注入，覆盖面有限；建议每次修复线上/评审发现的问题时都补一次注入记录。
- 事务与并发路径（两个审批人同时处理同一张单）没有注入实验，因为内存 SQLite 下难以稳定复现；
  该路径目前依赖唯一约束与条件更新兜底，后续可在 PostgreSQL 环境下补并发测试。
