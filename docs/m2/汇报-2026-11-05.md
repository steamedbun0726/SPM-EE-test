| 文档 | 结论 |

### 2. 修掉一个会直接导致演示失败的缺陷

原实现把整教室审批结果写进 `Seat.status`，而 `Seat` **没有时间维度**：
一次「某天 10:00–12:00」的审批，会让该教室所有座位在**所有日期**永久不可预约。

现在：`Seat.status` 只表达物理状态（可用/维修），时段占用由 `occupancies` 表达，
带 `source` + `refType/refId`，`explain()` 能直接回答「这个座位这个时段为什么不可约」。

### 3. 多级审批从「形式」变成「实质」

- 权限码拆成 `room.approve.l1` / `room.approve.l2`
- 不能审批本人提交的申请
- 同一审批人不能连续完成两级
- 审批通过前复查冲突，防止提交到审批之间被个人预约插入
- 状态迁移与占用写入在同一事务内

## 四、5 分钟演示脚本

1. 用 `teacher` 登录 → 整教室申请 → 选 CLASS-301，选一个已被占用的时段
   → **页面实时提示冲突并禁用提交**（preflight）
2. 换一个空闲时段 → 提交 → 生成 `RB-YYYYMMDD-NNN`
3. 用 `room_admin` 登录 → 审批队列只显示**一级**待审单 → 通过 → 状态仍为待审批，层级 1/2 → 2/2
4. 用 `approver` 登录 → 队列出现该单 → 终审通过 → 状态变为已通过
5. 回到「我的申请」→ 详情 → **审批链时间线** + **占用来源**（M2 / room_request / 单号）
6. 申请人在活动开始前撤销 → 占用释放

> 演示前需要 `npm run seed` 或直接启动后端（启动时自动迁移 + 种子）。
