# CI/CD 流水线说明

> 目标：尽可能早地自动部署到测试环境，测试失败则后续阶段不执行；生产发布需人工审批、可回滚、可追溯版本。

## 流水线阶段（本地脚本即雏形，可在任意 CI 平台配置）

```bash
# 阶段 1：构建 + 质量门禁（提交/合并自动触发）
cd backend && npm ci && npm run build && npm test -- --runInBand   # 测试失败则中止
cd frontend && npm ci && npm run build

# 阶段 2：测试环境部署（自动）
# 迁移 + 种子随应用启动自动执行（migrationsRun: true / seed on boot）

# 阶段 3：生产发布（人工审批）
# 打 tag → 回滚 = 部署上一个 tag
```

## 约定

- **构建**：提交与合并请求自动触发；任一环节测试失败，后续阶段不执行。
- **质量门禁**：测试不过不能合并；跨模块变更、公共层变更、schema 变更须经组内评审（MR Review）。
- **测试环境**：流水线自动部署，一次部署覆盖本组所有模块。
- **生产环境**：人工审批后发布；应可回滚；能说明当前运行版本（后端 `/api/health` 返回版本号与 commit，见 `backend/src/app.controller.ts`）。
- **发布协调**：约定部署窗口（如每工作日 22:00–24:00）或等效机制，避免某模块部署时其他模块集成测试误报失败。
- **Schema 演进**：结构变更以版本化迁移脚本提交（`backend/src/database/migrations/`），禁手工改库；从空库到最新版本可一次性重放（`npm run migration:run`）。

## 定时任务（提醒/违约/超时撤销/升级）生产部署提示

雏形的定时任务随 NestJS 应用进程运行。生产环境建议：
1. 独立运行一个 worker 实例只启用调度模块，避免多实例重复执行；或
2. 将调度逻辑抽为独立进程/容器，接入流水线。

## 验证清单（对应期末展示要求）

- [ ] 全新环境：`git clone` → `npm ci` → `npm run build && npm test` → 启动后迁移/种子自动执行
- [ ] 提交一次变更 → 触发构建与测试
- [ ] 一次包含 schema 变更的部署 → 说明数据如何演化
- [ ] 一次生产发布与回退（tag）
- [ ] 跨模块链路演示：M2/M3 状态写回 M1（后端有对应集成测试）
