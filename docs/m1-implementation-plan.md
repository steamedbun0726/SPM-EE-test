# M1 自习座位预约 — 分阶段实施指令

> 个人分支：`m1/dev`（参照 M2 开发者 Loong 的 `m2/dev` + `feat/m2-*` 模式）
> 依据清单：`docs/m1-tasks.md`（M1-01 ~ M1-12 + 待补项 + 增强 backlog）
> 提交规范：Conventional Commits，scope 用 `m1`（例：`feat(m1): ...`、`test(m1): ...`）
> 规则：**每一阶段完成，必须本地自测通过后推送一次 `m1/dev`**；分支保护只作用于 main，`m1/dev` 可自由推送。

---

## 阶段 0 · 分支初始化（本文件提交时完成）

- 动作：从 `main` 创建 `m1/dev`；提交 `docs/m1-tasks.md` 与本文档。
- 提交信息：`chore(m1): 初始化 M1 开发分支，纳入待办清单与分阶段实施计划`
- 推送：`git push -u origin m1/dev`（此后每次推送只需 `git push`）

---

## 阶段 1 · 补齐基线缺口：M1-05 院系隔离测试

- 目标：`requirements.md` 中唯一 🟡 项——「院系自习室仅对本院系同学开放」补自动化测试。
- 改动范围：`backend/test/m1-seats.spec.ts`（实体已含 `ownerDept`，预约/搜索已校验，只缺测试断言）。
- 验收命令：
  ```bash
  cd backend && npm test -- --runInBand
  ```
  新增用例至少覆盖：非本院系学生搜索院系自习室 → 结果不包含；非本院系学生预约该室座位 → 被拒并给出明确错误。
- 提交信息：`test(m1): 补 M1-05 院系自习室开放权限校验测试`
- 推送：`git push`

## 阶段 2 · 增强：签到二维码展示

- 目标：动态码之外，签到页展示与教室关联的二维码（Web 端可扫）。
- 改动范围：后端 `reservations.controller.ts` / service 新增二维码数据接口（基于现有动态码生成 QR 内容）；前端 `frontend/src/views/m1/SeatSearch.vue` 或签到页展示二维码。
- 验收：浏览器打开签到页可见二维码；录入等效编码仍可签到（回归 M1-06）。
- 提交信息：`feat(m1): 签到动态码升级为二维码展示`
- 推送：`git push`

---

## 阶段 3 · 增强：外部推送（邮件 / 微信服务号）

- 目标：预约前 15 分钟、开始后 10 分钟提醒，在站内通知之外接入邮件或微信服务号推送；外部渠道失败时降级站内通知。
- 改动范围：`backend/src/scheduler/scheduler.service.ts` 提醒分支 + 新增推送适配器；`system-config` 增加推送开关与配置。
- 验收：手动触发一次提醒，确认按配置发出外部推送；断网/配置缺失时仍落站内通知，不抛异常。
- 提交信息：`feat(m1): 预约提醒接入邮件/微信推送，失败降级站内通知`
- 推送：`git push`

---

## 阶段 4 · 增强：运营统计可视化

- 目标：`stats` 接口数据前端图表化（座位利用率、按自习室预约量、时段热力），服务运营管理员。
- 改动范围：后端 `stats` 若字段不足则扩展；前端新增运营看板页（归入 `frontend/src/views/m1/`）。
- 验收：运营管理员登录可见图表；数据与 `GET /api/m1/stats` 一致。
- 提交信息：`feat(m1): 运营统计看板可视化`
- 推送：`git push`

## 阶段 6 · 跨模块集成回归 + PR 合入

- 目标：收尾验证跨模块链路后，将 `m1/dev` 合入 `main`。
- 回归清单（来自 `m1-tasks.md` 第四节）：
  1. M2 → M1：二级审批通过 → 该室时段座位被占用，M1 搜索该时段返回 0；驳回/超时 → 回滚恢复。
  2. M3 → M1：报修上报 → 该室座位下架（搜索 0）；验收 → 恢复。
  3. 追溯：`seat_status_logs.source` 分别为 `M2` / `M3` / `M1`。
- 验收命令：
  ```bash
  cd backend && npm test -- --runInBand && npm run build
  cd ../frontend && npm run build
  ```
- 提交信息：`chore(m1): 跨模块集成回归验证收尾`
- 推送：`git push`
- 合入：在 GitHub 上对 `main` 发起 PR（标题带 `M1`），等 CI 两个检查（后端构建与测试 / 前端构建）通过并经组内评审后合入。

## 附：开发期注意事项

- 每次开始前 `git pull origin main` 后 `git merge origin/main`（或 `git pull`），避免与 M2/M3 兄弟分支冲突；**冲突由人处理**（AGENTS.md 约定）。
- 涉及公共层（shared/）或 schema 的变更，须先与 D 归属模块组对齐并经组内评审。
- 测试必须真实断言行为：故意破坏实现后应能看到测试失败（AGENTS.md 第 5 节）。
