## 为什么按模块拆文件

原先是单文件 `docs/requirements.md`，三个模块并行编辑同一份表格、各改各的段。2026-11-05 核对时发现该文件已分叉成三个版本，没有一份是完整的：

| 段 | main | PR #1（M2） | 本地 M3 分支 |
|---|---|---|---|
| D | 7 | 7 | 7 |
| M1 | 12（M1-05 🟢） | 12（M1-05 🟡） | 12（M1-05 🟡） |
| M2 | 6 | **13** | 6 |
| M3 | 6 | 6 | **31** |
| A | 3 | 3 | 3 |
| I | 3 | **4** | 3 |

拆成按模块一文件后，各模块只改自己的文件，结构上不再产生冲突。`docs/requirements.md` 保留为跳转存根，指向本目录。

| D1 身份与权限 | D-01、D-02、D-07 |

| D4 通知 | D-05 |

跨模块共性项：

- **定时任务**（提醒 / 违约 / 撤销 / 升级 / 挂起超期）目前依赖应用运行中的调度；生产环境需独立调度容器，否则多实例部署会重复触发。所有定时扫描必须幂等，`escalateOverdue` 曾因不推后窗口而每轮重复命中同一单。
- **通知渠道**：邮件、微信推送为 `NotificationsService` 的抽象接口，雏形只实现站内通知，其余渠道未接入。

## 维护规则

1. **各模块只改自己的文件**；跨模块条目改 `i.md`；D 层条目改 `d.md`。出现需要同时改两处的情况，说明边界没划清，先谈边界。
2. **状态从 🔴/🟡 转 🟢 必须附证据**：具体测试文件名，或故障注入记录（注入什么缺陷、哪几条变红）。只写「接口测试」不算证据。
3. **条目只增不删**。确需作废的保留 ID，状态改为 🔴 并注明作废原因与替代条目，禁止复用编号。
4. **新增条目先在所属文件追加，再更新本文件索引表的条数统计**。本文件的统计数字与实际不符时，以模块文件为准。
5. **核对待办时不要只看本地分支**。M2 的条目在 PR #1，M1 的在 main，本地分支滞后 9 个提交。
