## 阅读顺序

```
01 调研 ──结论──▶ 02 需求 ──输入──▶ 03 方案 ──评审──▶ 编码
                                      │
                                      ▼
                                   ADR-0002（关键决策与备选）
                                      │
04 开发记录 ◀──证据回流────────────────┘
```

- 只想知道**要做什么**：读 02 的第 4 节（功能需求），12 条需求带优先级与验收标准。
- 想知道**怎么实现**：读 03 的第 2、3、4 节（状态机、数据模型、接口）。
- 想评审**风险点**：读 03 第 10 节（风险）与第 11 节（评审要点）。
- 想知道**做到哪了**：读 04 的阶段划分表与「阻塞与待决」。

## 范围约定

一期（P0）范围冻结为 **M3-07 ~ M3-12**：座位粒度下架、事件时间线、改派、返工、权限补全、升级处置。评审通过后不再追加需求，新增想法一律进二期或记录为「本期不做」。

## 与其他文档的关系

- `docs/requirements.md`：项目级需求基线。本目录的 02 是其 M3 章节的展开，实现完成后需**回写**状态与验证方式。
- `docs/backend-contracts.md`：模块间接口契约。新增接口后需同步更新其 M3 章节。
- `AGENTS.md`：工程约束（座位状态必须走 `SeatStateService`、禁止手工改库、测试必须真实断言）。本目录所有方案均遵守该约束。
