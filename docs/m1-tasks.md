## 一、需求基线任务（12 项）

### 预约与搜索

- 🟢 **M1-01 查看可用自习室与开放时间**
  验收：学生端能列出可用自习室及其开放时段（开放时间由系统配置控制）。
- 🟢 **M1-02 按条件搜索座位**
  条件含：自习室、日期、时段、是否靠插座。验收：各条件组合过滤结果正确（对应接口测试）。
- 🟢 **M1-03 整点小时预约，单次最多 4 小时（系统参数可调）**
  验收：超过 4 小时被拒绝；修改 `maxHoursPerBooking` 系统参数后上限随之生效（参数注入的单元测试）。
- 🟢 **M1-04 同一座位同一时段不重复预约（冲突检测）**
  验收：冲突场景返回明确错误并拒绝预约（三方冲突：M1 预约 + M2 审批占用 + M3 下架）。

### 权限与隔离

- 🟡 **M1-05 院系自习室仅对本院系同学开放** ← **待补测试**
  现状：实体含 `ownerDept`，预约时已校验；验收：非本院系学生搜索/预约院系自习室被拒绝。**缺单元/接口测试**（见 `requirements.md` 待补项）。

### 签到与违约

- 🟢 **M1-06 动态编码签到（Web 录码）**
  验收：错误码签到失败；正确码签到成功且预约状态流转（集成测试已覆盖）。
- 🟢 **M1-07 预约前 15 分钟推送提醒**（定时任务 → 通知）
- 🟢 **M1-08 预约开始后 10 分钟未签到再次提醒**
- 🟢 **M1-09 预约开始后 15 分钟未签到：自动取消 + 释放座位 + 记一次违约 + 提醒**
  验收：调度器触发后预订取消、座位恢复可约、`violation` 落一条记录、学生收到通知。

### 历史与运营

- 🟢 **M1-10 历史预定查询 + 再次预订同一座位**（`rebook` 复用原行，非新开记录）
- 🟢 **M1-11 运营统计：自习室与座位预约情况**（`stats` 接口）
- 🟢 **M1-12 座位状态写入来源追溯（M1 / M2 / M3）**
  验收：所有状态变更经 `SeatStateService` 落入 `seat_status_logs`，`source` 字段可区分来源。

## 四、跨模块集成验收点（回归必测）

1. **M2 → M1**：整教室申请二级审批通过 → 该室时段内座位被占用（M1 搜索该时段返回 0）；驳回/超时 → 回滚恢复。
2. **M3 → M1**：报修上报 → 该室座位下架（搜索 0）；验收通过 → 恢复。
3. **来源追溯**：以上变更在座位的 `seat_status_logs` 中 `source` 分别记为 `M2` / `M3`。
